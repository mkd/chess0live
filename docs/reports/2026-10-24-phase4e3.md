# Phase 4E.3 — automatic Python tool setup

Date: October 24, 2026. Parent: `81d2bae2f8daf005c13d9bdd134dc4753a72d059`.
Scope: external Python tooling; no chess/search/evaluation change.

## Delivered behavior

`python3 tools/batch_positions.py /path/to/engine` now prepares its pinned chess
dependency automatically. The shared `python3 tools/run.py <script.py> <args>`
launcher provides the same setup for other tools/tests. Forty-four existing
Make entrypoints needing the direct/transitive chess dependency use it;
standard-library-only builds and core tests remain independent of these packages.
`make tooling` prepares the environment; `make test-tooling` checks the setup and
batch runner. See the [user guide](../TOOLS.md).

The managed cache defaults to ignored `.local/tooling/`, with an optional local
directory override. Package identities and archive hashes are pinned in
`tools/python-packages.json`: chess 1.11.2, setuptools 80.9.0 and wheel 0.45.1.
Archives are checked before use; pip only receives local hash-checked archives,
with indexes, dependencies and build isolation disabled. Python supplies its
bundled pip via `ensurepip`. The source package builds using the pinned tools.

The setup checks imports, versions, isolation and ownership before reusing an
environment. Concurrent launches share a setup lock; incomplete owned installs
are rebuilt. Cached archives support offline reconstruction. Foreign/unowned
directories are preserved. Copied interpreters keep existing tests that resolve
`sys.executable` inside the environment. POSIX CLI handoff preserves the actual
tool's PID; installer cancellation/timeout stops its process group, and inherited
locks prevent an overlapping setup if the parent is hard-killed.
