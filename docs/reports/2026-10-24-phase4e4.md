# Phase 4E.4 — target setup and local toolchain provisioning

Date: October 24, 2026. Parent: `55d0ea1deab18d178e5d2bba4ecb452b03db1394`.
Scope: compiler discovery/provisioning and Make integration; no engine change.

## Delivered workflow

`make portable` detects the host, selects a working compiler and builds in
`build/portable/<target>-generic-release/`. `TARGET=...` selects a cross-target;
`toolchain-plan` reports routes without setup, and `toolchain-check` prepares and
compile/link-checks the selected route without executing a probe or building the
engine. The same interface is available through `tools/build.py` on hosts with
Python but no initial Make installation. See the
[user guide](../PORTABILITY.md#automatic-target-setup).

Discovery covers installed native/target-prefixed compilers for all six project
targets. For Windows targets, the automatic fallback provisions official
LLVM-MinGW 20261020/Clang 23.1.4 into an ignored local cache. Five host assets have
pinned URLs, sizes and full SHA-256 hashes. Windows-host bundles include their
own Make/shell; this route is implemented but not natively verified. Linux
cross-compilers/target libraries and Apple's SDK remain explicit prerequisites.
No global package-manager/compiler configuration is changed.

The cache verifies archives, stages extraction, preserves internal compiler
aliases and upstream notices, rejects unsafe paths/escaping links/special files,
and publishes a complete installation. Offline cached archives and the earlier
verified archive under `build/toolchains/` are reusable. Each setup/build saves
fresh probe/build logs and a JSON result; successful builds include the binary
hash/header and effective compiler configuration. Failed checks do not certify
an old output. Runtime verification remains a separate action.

The optional Make `CXX_EXECUTABLE` interface passes a literal compiler path
through an argv adapter, including spaces and shell/Make metacharacters. It
preserves target-selecting symlink basenames. Legacy `CXX` commands/wrappers
remain available. Bare automatic Make targets let Python detect the host rather
than relying on `uname`, which may be missing on Windows ARM64.

## Limits and next checkpoint

Native Windows setup, bundled shell/Make and process-tree cancellation remain
unverified; the Linux x86-64 and Windows host archives were pinned from official
metadata but not downloaded/exercised here. There is no pinned RISC-V-host
LLVM-MinGW bundle. Linux system compiler provisioning and Apple SDK installation
are not automated. The setup probe checks a complete toolchain with standard
flags, not arbitrary custom-sysroot configurations. Cached-install checks cover
ownership and compiler wrappers, not every installed file. These limits are
documented rather than presented as complete host/target certification.

No search/evaluation/default change, Elo/NPS claim, release, long puzzle/match
campaign or schedule was added. No CuteChess retest is required for the unchanged
engine. Next is **Phase 4E.5: network inspection and qualification tooling**,
followed by export/training/selection with recorded provenance and experience.
