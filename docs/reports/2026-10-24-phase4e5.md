# Phase 4E.5 — network inspection and qualification

Date: October 24, 2026. Parent: `360da0177f228b67b08176f5092aa9fc9792f790`.
Decision: the bounded tooling checkpoint is complete. No engine/default change,
strength promotion or release follows.

## Deliverable

`tools/network.py` and `make network-inspect` / `network-qualify` provide a
standard-library-only external workflow. Inspection hashes the complete file,
recognizes the SFNNv16 header and separates pinned provenance from unverified
declarations. Unknown training games, positions and epochs remain null.
Digest-bound metadata templates provide a small versioned provenance format.

Qualification performs the existing full scalar/native/reference integer-stage
comparison for arbitrary SFNNv16 weights. The historical `--network` path still
requires the manifest payload. Explicit candidate mode skips pinned golden
scores only when the candidate differs from that payload. Local full decoding,
incremental/full-refresh agreement and bounded wrapped outputs are checked
before evaluating the candidate with the external reference.

Every run binds the network, corpus, source and five executable identities.
Fresh reference builds use the pinned committed tree rather than dirty cache
files or stale objects. Locks serialize work/cache reuse; bounded subprocesses
are stopped on interruption, with diagnostic output retained. The user-facing
command requires a fresh output directory or creates a unique one automatically.
No file selection, network installation or training occurs.

## Limits and next checkpoint

Agreement covers the recorded finite corpus, not every possible input. Metadata
claims are not independently authenticated; no training-data totals, rating or
strength were inferred. A compatible alternative still needs tactical and
matched-resource game evidence before a playing-strength decision. Native Windows
execution/process-tree cancellation remains unverified. No UCI/GUI gameplay,
sanitizer/race suite or long puzzle/match campaign was rerun for this tooling-only
change; the engine and stable GUI bundle are unchanged.

Next is **Phase 4E.6: reproducible training and export tooling**. Pin a compatible
trainer, describe its local prerequisites and reproducible configuration, record
