## Implementation

Each worker can allocate a private one-ply table indexed by the previous and
current colored moving piece/destination. Quiet moves receive the extra score
only after TT, promotion, capture, killer and countermove priorities. Completed
ordinary quiet cutoffs reward the winner and penalize the searched quiet prefix
using bounded gravity. Root, quiescence and speculative searches do not consult
or train it. Original pieces are retained as context across promotions.

Storage is 589,824 signed 16-bit entries, nominally **1.125 MiB per worker**
outside Hash. Disabled workers own no table. Allocation is transactional across
all workers and simultaneous move-hint changes. Clearing/new games/policy
transitions erase learned state; new searches age it. Diagnostics expose
allocation and lookup/update counts after joining all workers.

Although no pruning predicate changed, move ordering can alter LMR selection.
This implementation cannot promise unchanged strength on untested positions.

## Validation

Native macOS ARM64 generic release, Apple Clang 21.0.0, C++26 mode:

- Full `make test`: core/perft, UCI lifecycle, resource policy, incremental NNUE,
  dense arithmetic, exchange, ordering, history-prefix, TT hints, search and
  time-policy checks passed.
- New table checks passed, including 20,000 independent arithmetic updates,
  all 768 context identities, isolation, bounds, decay, clearing and allocation
  failure. The reported 2,401,659 assertions include complete-table zero checks;
  they are not that many distinct positions.
- 36 direct search groups passed, including ordering priorities, special moves,
  speculative exclusion, interruption/restoration, one/four-worker lifecycle
  and five deliberately injected allocation failures.
- 60 UCI cases passed, including strict parsing, legal PV/best/ponder moves,
  terminal roots, limits, active option changes, diagnostics and one/four workers.
- Existing countermove checks (57 cases), SMP UCI checks (43 cases) and direct
  ProbCut isolation/search tests passed after integration.
- The new table/direct/UCI checks also passed separately under ASan+UBSan and
  ThreadSanitizer. These checks do not establish foreign-platform runtime safety.

The first broad run failed its final PATH-launch test because the deeply nested
isolated build had no adjacent default network when launched outside the repo.
The saved reproduction reports `network not found` and `bestmove 0000`, before
any search. Adding an ignored `networks` link beside that test executable made
the same command return the restricted legal move `e2e4`; the full suite then
passed. No engine change or weakened assertion was used. Both logs are retained.
