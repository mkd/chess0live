# Phase 4F.3 — combined search policy audit

Date: October 24, 2026. Engine baseline: `ccb66a4`; preparation commit: `7444f21`.
Status: full tactical comparison and independent audits completed. **Keep current
defaults; park the combined package and its unstarted 512-game campaign pending
focused diagnosis.** This is a conservative progression decision, not an Elo
result. No engine source, playing default or release changed.

## Purpose and comparison

The owner measured approximately 21.4% fewer nodes and less time to depth 10 at
the starting position with all search experiments enabled. The final move,
score and PV matched, but intermediate results differed. That observation
motivates a direct package comparison, without requiring individual component
wins first. It does not establish an Elo gain.

The [protocol](../experiments/phase4f3.md) fixes the same current executable and
pinned NNUE for both roles. Both retain conservative LMR. The combined package
also enables deeper quiet reductions, SEE capture ordering, countermove ordering,
verified null-move pruning, reverse futility, quiescence SEE filtering and ProbCut.
Time policy, network, Hash, overhead and other settings remain matched.

## Tools and safeguards

The tactical runner freezes the owner's 39 FENs without changing the editable
batch runner. It compares serial fresh processes with eight threads and Hash 64,
alternates role order, saves raw analysis and independently checks move legality.
The smoke uses one second per search; the full run uses 60 seconds. Reported mates
and supplied mate annotations are separate from any independently proven mate.

The match launcher prepares four shards totaling 512 games/256 color-reversed pairs,
with fresh full-history opening roots, 60+0.6 clocks and one thread per engine.
Existing referee, protocol-clock and raw-audit code is reused. Current option
validation covers LMR=true and all optional features explicitly. Historical
launchers, data and expired daytime permissions remain untouched.

Both workflows retain failure evidence and reject output-directory reuse, changed
inputs, insufficient resources and computer-sleep/monitor gaps. UTC and monotonic
observations are checked; the next 07:00 Helsinki deadline is calculated across DST.
No automatic schedule is created. Full runs are sequential and require a permitted
time window or a fresh owner exception.

## Completed validation

`make test-phase4f3` passed **128 checks**: 17 opening/provenance checks,
26 launcher/lifecycle checks, 53 independent-auditor checks and 32 puzzle-runner
checks. These include corrupted raw game/clock/option evidence, cleanup,
forward/backward clock changes, both DST transitions, permission boundaries,
invalid PVs, missing results, changed inputs and partial failures. Synthetic
referee fixtures exercise raw game replay without starting a real match.

The four opening shards contain 256 unique legal, nonterminal roots, with
32 roots per side to move in each shard. All full histories replayed legally;
the deterministic generation had no rejected attempts. Full local-source
verification checked exclusions covering 217,220 canonical roots across 136
sources and 2,284 saved games, including all 512 October 22 LMR games. The
compact public exclusion catalog contains 2,195 roots; saved-game exclusion
provenance is verified separately. No actual PGNs were malformed. Shared stems
remain an explicit independence limitation.

Real search-free preflight configured both roles successfully, followed by a
passing independent readiness audit. It verified current defaults, all applied
options, corpus/input identities and a six-GiB reservation for four active
searches/eight resident engines. No held-out position was searched. The host
reported 18 logical CPUs and 64 GiB RAM, with the daytime budget allowing nine
workers. A process snapshot before the smoke found no other chess engines.

The eight-thread smoke ran from 21:35:18 to 21:36:55 Helsinki, approximately
97 seconds including fresh-process setup. All **39 positions / 78 searches**
completed, with no illegal moves, protocol errors, tablebase hits, receipt
overruns, resource violations or detected suspension. Independent raw replay
validated **453 iteration records and 2,588 PV moves**, every final best/ponder
move, the exact sent option packages and retained source identities.

Both configurations reported zero positive mates within the one-second budget.
Best moves matched on **38/39** positions. Position 22 differed: defaults chose
`d1h5` at +5.72, while the combined package chose `d1d4` at +6.61. Final scores
differed at 11 positions. These observations do not establish which move is
better, a reproducible tactical regression, or a strength improvement.

Measured raw go-to-bestmove receipt times ranged from 0.980230 to 0.980974 seconds;
the configured 20-ms overhead explains the early stop. Maximum observed clock
discrepancy was 0.157 ms and monitoring gap 0.258 seconds. Main-loop receipt
timestamps include queue/I/O delay; they are not reader-thread arrival times.
Engine-reported time/NPS is not independently reconciled with those receipts.
The fixed receipt tolerance is 250 ms, separate from a five-second hang watchdog.
Eight-thread SMP is nondeterministic and each configuration was run once per
position. Fresh processes exclude cache carryover and game-history effects.

After the smoke, a launch-permission-only extension added explicit
`--allow-daytime` support for the full puzzle run. It requires fresh owner
authorization and preserves all resource, cutoff and timing checks. The exact
pre-extension runner/test files are retained under the smoke's `tool-snapshot/`
and match its before/after hashes. The search logic did not change; this extension
was tested with synthetic permission/window cases, without repeating searches.

## Full 60-second comparison

The owner explicitly authorized a daytime exception for this comparison only.
It ran from **21:49:05.533 to 23:07:27.601 Helsinki**, 78 minutes 22 seconds,
on October 24. All **39 positions / 78 searches** completed. Each fresh engine
received 60 seconds, Threads=8, Hash=64 MiB, Move Overhead=20 ms, classic timing,
Ponder=false and disabled tablebases. Role order alternated by position; searches
ran serially on the same frozen executable and network. The two-GiB reservation
and eight requested workers fit both the daytime and nighttime policy budgets.
Foreground `caffeinate -i` prevented idle sleep; no automatic schedule was created.

Defaults reported M7 at positions 1 and 2, and M9 at position 15. All-on reported
M9 at position 1, M7 at position 2, and +15.99 at position 15. It produced no new
positive mate report. A legal line ending in mate does not prove forced mate
against every defense; the supplied annotations are not independently proven here.

Of the 36 positions with centipawn scores in both configurations, defaults gave
a higher score at 26, all-on at one, and nine tied. Defaults completed a deeper
nominal iteration at 29 positions, all-on at one, and nine tied. These are
observations, not accuracy or strength scores. Centipawns do not measure distance
to mate, and the common best moves do not establish equally strong play.

Independent raw replay passed **741 iteration records and 6,280 legal PV plies**,
every final best/ponder move, all sent options and retained source identities.
All 2,572 resource/clock observations passed. Monotonic go-to-bestmove receipts
ranged from 59.980226 to 59.983569 seconds; wall receipts ranged from 59.962967 to
59.983261 seconds. The largest observation gap was 2.252246 seconds and maximum
wall/monotonic discrepancy 21.704 ms. No protocol error, illegal move, receipt
overrun, resource-policy violation or detected suspension occurred. The 250-ms
receipt tolerance is separate from the five-second hang watchdog.

Receipts are main-loop queue observations, not reader-thread arrival times.
The configured thread count/resource reservation is not an OS utilization
measurement. Raw logs contain fresh-session handshakes/options/newgame/quit;
the frozen runner creates a fresh process for each case. Process IDs and exit
codes were not recorded, so raw logs alone cannot prove distinct process identity
or successful teardown. Eight-thread SMP is nondeterministic; the original sample
contains one search per configuration/position. These exposed puzzles do not
replace held-out match evidence.

## Decision and next checkpoint

**Retain defaults and park the all-on package's match campaign.** The faster
starting-position depth-10 observation did not generalize to these tactical
searches. There is no accepted strength evidence for promotion, and the repeated
mate-report deficit is worth diagnosing before a long match. The 512 games remain
unstarted; no held-out root was searched. This is not a failed statistical match
gate or a claim that all-on is weaker overall.

Next is **Phase 4F.4: focused diagnosis of combined-package cost and SMP
interactions**. Use the already-exposed 15-root profiling corpus, matched one-
and eight-thread configurations and bounded measurements to distinguish added
per-node cost from search-tree or worker interaction effects. Component removal
may diagnose a package without demanding that each feature win individually.
Do not tune thresholds against these 39 puzzles or expose the held-out match
roots for profiling. Choose one concrete implementation candidate from the
measurements, retain correctness guards and require strength evidence for any
search-policy default change. Avoid another broad optimization checklist.

The existing match protocol and opening corpus stay frozen and unplayed. If a changed candidate
later warrants a match, declare its identity, comparison and acceptance rule
before play. Long runs still need a permitted window or specific owner exception;
this puzzle authorization does not authorize a daytime match. No automatic
campaign, schedule, release or rating follows from this checkpoint.
