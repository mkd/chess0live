Date: October 24, 2026. Parent: `3278faf7bd400fe698d95099afeb3cc348b28afc`.
Decision: the bounded native macOS managed-network workflow is complete.
No engine strength promotion, new playing network or release follows.

## Delivered behavior

`tools/managed_network.py` provides registration, list/status, select/default,
revert, launch configuration and managed execution. Registration copies the
payload and optional metadata into an ignored local entry, performs a fresh
complete qualification, and publishes an immutable name only after success.
The original file and default network stay unchanged. Catalog updates use a
process lock and atomic replacement; failed or interrupted operations preserve
the active choice. Repeated selection does not discard rollback history.

`tools/network_receipt.py` rechecks retained network/provenance identities,
outer/nested reports, the complete corpus and six output files, five test
binaries, reference sources and current local evaluator/qualification sources.
Stale evidence is visible in status but cannot authorize selection or launch.
Missing/corrupt records fail; they never silently restore a different network.
The original `default` has a separate, explicit manifest-pinned identity scope.
Local integrity records are not signed attestations. Declared game/sample counts
remain declared; neither matching outputs nor those counts prove strength.

The engine's only source change is `--eval-file PATH`. It loads that exact file
before UCI starts, advertises the resolved launch path as the EvalFile default,
and preserves later explicit UCI overrides. Invalid files fail before UCI output;
malformed arguments fail with usage status. No-argument behavior is unchanged.
The managed launcher inherits stdio directly without a protocol proxy. A saved
GUI EvalFile can override a launch argument and must be updated deliberately.

The catalog certifies the retained finite network comparison against this
checkout's evaluator sources. An arbitrary executable supplied to `--engine`
is fingerprinted, not independently certified as built from those sources.
Use a current chess0live build; older builds reject the launch argument.

## Review corrections and evidence

Review found that hashing receipts before checking their file type/size could
block on a FIFO, and that an `entries` symlink could escape the store. Both are
rejected before access and have regression cases. Final review also found that
a missing catalog in a nonempty store could look like a fresh default; it now
fails closed, as do symlinked catalogs. These were tooling review findings;
no failed network qualification or gameplay regression was observed.

Evidence is under `results/phase4e7-20261024/`: `registration.log`, the complete
catalog entry qualification tree, `final-managed-tests.log`, `catalog-tests.log`,
`receipt-tests.log`, `eval-file-cli-tests.log`, `uci-tests.log`,
`managed-integration.json`, direct/managed transcripts,
`default-search-parity.json`, `final-audit.json` and `preservation.json`. The integration script is
retained there; payloads, generated binaries, reports and catalogs stay out of Git.

Real execution was macOS ARM64 with modest local serial checks and one compiler
job for qualification. Other host managed-launch execution, GUI clicks,
new sanitizer/race coverage, broader runtime acceptance and network playing
strength remain unverified. Evaluation/search algorithms and playing defaults
are unchanged. Existing native/VM/emulated engine coverage is historical evidence,
not a claim that this new workflow ran on every host.
