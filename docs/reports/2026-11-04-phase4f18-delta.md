# Phase 4F.18 — delta pruning development checkpoint

Date: November 4, 2026. Implementation and short development screen complete;
full tactical and playing-strength qualification pending.

## Decision

Retain the independently authored **QSearch Delta Pruning** experiment, with
its default **false**. The fixed screen shows work savings in both cache
conditions and no final depth-6 best-move or displayed-score changes across the
15 exposed roots. This warrants the prepared full puzzle checkpoint. It does
not establish an Elo gain, tactical equivalence, or a reason to promote settings.
No games, release, future schedule, or GitHub push were performed.

The [prospective protocol](../experiments/phase4f18-delta.md) fixed one rule before
implementation/measurement. Ordinary interior quiescence scout captures may be
skipped when original stand-pat plus a victim allowance plus 400 internal units
is strictly below original entry alpha. Allowances are pawn 400, knight 1280,
bishop 1320, rook 2000, queen 3600, derived from four times this engine's local
ordering values. They are engineering allowances, not proved NNUE bounds.
Protected checks, terminal children, promotions, en passant, speculative modes,
score bands, draw-sensitive histories, advanced pawns and sparse endings retain
the ordinary path. Actual child inspection is reversible on skip/stop/failure.
Delta receives the first skip opportunity when combined with SEE; the existing
SEE policy is otherwise preserved. Policy changes clear reusable search state.
No Hyperion, Gargantua or Stockfish production code or testing assets were reused.

## Correctness and preparation failures

Native, forced-scalar, Address/UndefinedBehaviorSanitizer and ThreadSanitizer
builds passed the new direct production-branch suite, general Search API/policy
checks and **93 bounded UCI cases each**. The direct suite verifies both colors,
strict deficit boundaries, actual skipped children, checking mates/nonchecking
stalemates, real node-limit/external-stop/allocation-failure restoration,
board/history/NNUE state, SEE precedence, diagnostics parity, policy reset and
one/four-worker accounting. The UCI suite verifies legal PV/best/ponder moves,
option parsing, limits, stop/ponder/quit, reuse and optional-policy composition.
A bounded activation search in every build recorded 13,821 eligible nodes,
391 proposed captures, **317 actual skips and 74 protected checking captures**.
These counters are separate from the uninstrumented timed screen.

Native full core/UCI, NNUE, exchange, search/order/history, time and resource
regressions passed. NNUE coverage includes 537 parser/incremental comparisons,
360 update-arithmetic cases, 84,126 dense-output comparisons and 1,273 feature
transitions. Native and TSan each passed **43 existing SMP lifecycle cases**.
NNUE production arithmetic is unchanged; no fresh external-reference oracle or
foreign-platform execution is claimed. All execution here is local macOS ARM64.

Preserved preparation failures:

- The first 18-test screen-tool run had two failures and four errors. The reused
  start-position-only parser rejected FEN roots; the negative default-option
  fixture also incorrectly expected no earlier parent cells. Full-history/FEN
  parsing and that assertion were corrected. The second run passed all 18.
- The first direct branch run failed the stalemate count assertion: both queen
  and king could legally capture the pawn. The revised fixture explicitly has
  one tactical capture and derives its deficit window from real stand-pat.
  It passes in all four builds. No production rule or margin was changed.
- Sandbox process inspection was denied; an authorized OS process read then
  verified cleanup. No process was killed to obtain a passing result.

Independent code review found no blocking production issue. The independent
raw auditor passed **21 engine-free tests**; the earlier 20-test receipt remains.
The immutable freeze note says 20; its auditor hash is the final 21-test version.
This reporting correction leaves the frozen file intact.

## Frozen screen and independent audit

The owner freshly confirmed LM Studio paused, AC power and Automatic mode.
Exactly **150 searches in 90 serial engine sessions** completed in 44.741 seconds:
60 parent/off equivalence searches, 60 off/on depth-6 cold/warm searches, and
30 fresh 500-ms off/on searches. There was one observation per cell, alternating
role order, Threads 1, Hash 64 MiB, classic time policy, Move Overhead 20 ms,
conservative LMR on, MVV-LVA, all other experiments/Syzygy/diagnostics off.
No warmup, retry, replacement cell, discarded run or retuning followed results.
Warm cells retain the table and learned move history; they do not isolate TT
benefit alone.

Independent raw replay passed all 150 searches, 90 complete ordered session
transcripts, legal PV/best/ponder moves, 42 asset identities, complete matrices,
recorded cleanup and **30 exact parent/off pairs**. Exact signatures include
depth/seldepth/nodes/displayed score/PV/best/ponder, excluding the predeclared
time/NPS/hashfull fields; raw hashfull is range-checked and retained. No failures,
forced kills or artifact drift occurred. All 90 exits were zero; a subsequent
OS check found every recorded PID absent and no related engine/build process.
**LM Studio was released immediately after cleanup confirmation.**

Uninstrumented UCI exposes total nodes and normalized cp/mate scores. It does
not expose quiescence-only nodes or internal integer scores; both are explicitly
unavailable rather than reconstructed. This limitation was disclosed in the
protocol before measurements. Quiet-host confirmation is not an OS utilization
measurement. This small exposed sample is not statistical speed qualification.
